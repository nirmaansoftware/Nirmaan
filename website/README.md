# Nirmaan website (nirmaan.online)

Static marketing site. Pages are plain HTML **generated by Eleventy** from `src/`.
The generated site is committed in `public/`, so Vercel deploys it with no build step.
One hand-written stylesheet, a few small scripts, no client-side framework.

## Deploy

Vercel project for **nirmaan.online** with **Root Directory = `website/public`**.
Vercel serves only that folder, so the sources (`src/`, `.eleventy.js`, `package.json`,
`brand/`) are never published. Rebuild and commit `public/` with every source change.

## Run locally

    npm ci             # once
    npm run watch      # rebuilds on save and serves at http://localhost:8080
    npm run build      # one-off rebuild of public/

Commit a source change before you build: `sitemap.xml` dates each page by the
last commit that changed its template (pages made from data also count
`src/_data`), so a build made before the commit carries the old date.

## Where things live

| Path | What it is |
| --- | --- |
| `src/*.njk` | One file per page. Page copy lives in its front matter (lists, steps, FAQ), and the markup loops over it. `plan.njk`, `care.njk` and `service.njk` are paginated: one page per package (`/pricing/<id>.html`), care plan (`/pricing/care/<id>.html`) and service (`/services/<id>.html`). |
| `src/_includes/base.njk` | The shared `<head>`, plus the page intro and closing call to action, rendered from each page's `head:` and `cta:` front matter. |
| `src/_includes/nav.njk`, `footer.njk` | Site header (with theme toggle and mobile menu) and footer. |
| `src/_data/site.json` | **Contact details, social links and where enquiries are sent.** Anything left empty isn't rendered anywhere on the site. |
| `src/_data/pricing.json` | **Every price and plan detail**: packages, care plans, estimator, payment schedule, FAQs. Feeds the pricing page, the plan and care-plan pages, the homepage and the estimator. |
| `src/_data/services.json` | The service catalogue, with each service's problems, usual package and related services. Feeds the Services page, the service pages, the homepage rail and the footer. |
| `src/_data/navLinks.json` | Navigation order. Also sets page-transition direction and the sitemap. |
| `src/static/` | Hand-written files, copied to `public/` unchanged: `styles.css`, the scripts, `vercel.json` (redirects and security headers), `robots.txt`, favicon, `og-image.png`, `apple-touch-icon.png`, and `assets/motion/` (generated by `npm run masks`). |
| `public/` | **Generated. Never edit by hand.** Everything Vercel serves. |
| `brand/` | Logo source artwork. Not deployed. `logo-selection-2.png` is an earlier candidate, kept for reference. |
| `scripts/` | `render-assets.mjs` (`npm run assets`: link-preview and touch icons) and `build-mask.mjs` (`npm run masks`: page-transition masks). |
| `.eleventy.js` | Build config (input `src/`, output `public/`) plus the `{% logo %}` and `{% glyph %}` shortcodes. |

## The design system in one paragraph

Everything comes from the logo: a 5×5 pixel grid, a heavy grotesk (Archivo) and a
monospace descriptor (JetBrains Mono), with Hanken Grotesk for body text. Corners
are square and structure is drawn with hairlines. The one accent is blueprint blue.
Any 5×5 pattern can become an icon: `{% glyph "10001/11001/10101/10011/10001" %}`
draws the logo, and each service in `services.json` has its own pattern. All colours
are CSS custom properties at the top of `src/static/styles.css`, each defined once for
light and again for dark.

## Scripts

| File | Purpose |
| --- | --- |
| `src/static/contact-form.js` | Contact page. The three-step, problem-first intake: problem → optional context → timing and contact. Arriving from a plan, care plan or service (`?plan=`, `?care=`, `?service=`) shows what they're asking about and sends it as `interest`. Sends through Web3Forms (`web3formsKey`) or posts JSON to the Nirmaan OS intake API (`intakeEndpoint`), whichever is configured in `site.json`. If neither is set, it says plainly that the form isn't connected and shows the email address. |
| `src/static/site.js` | Every page. Nav state and reading-progress bar, theme toggle (system / light / dark, remembered), mobile menu, scroll reveal, drawn section rules, price count-ups, the card spotlight, and the scroll scenes (the layer stack that pins on wide screens, the services rail that pins on any screen tall enough, the process timeline, the step index). |
| `src/static/hero.js` | Homepage only. The pixel N assembling on the construction grid, right of the headline. |
| `src/static/estimator.js` | Pricing page. The budget and timeline estimator. Prices and durations are `data-*` attributes written from `pricing.json`. |
| `src/static/page-transitions.js` | Every page. Pages are built block by block: a stepped mask (`assets/motion/`) with direction from the menu order, plus the title morph from a card into its page's heading. Browsers without view transitions get the same block build from an overlay. |

All motion is progressive enhancement. With JavaScript off, or with the visitor's
"reduce motion" setting on, every section renders complete and nothing animates.

## Configuration

1. **Contact details.** Fill in `src/_data/site.json` (email, phone, WhatsApp number with
   country code, social URLs), then rebuild.
2. **Enquiry form.** Set `web3formsKey` (emails each enquiry) or `intakeEndpoint`
   (`https://os.nirmaan.online/api/intake`, which creates a LEAD-### in the OS). The form
   never claims a message was sent when it wasn't.
3. **Brand images.** `og-image.png` and `apple-touch-icon.png` are rendered from HTML by
   `npm run assets` (needs Google Chrome). Logo sources are in `brand/`.
